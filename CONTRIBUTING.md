# Правила работы с репозиторием

## Структура папок
- `/docs` - Документация (отчеты, спецификации)
- `/src` - Исходный код
- `/uml` - Диаграммы UML

## Именование файлов
Шаблон: `ТипДокумента_Описание_Версия.pdf`
Примеры:
- `SRS_Требования_v1.0.pdf`
- `UML_ДиаграммаКлассов_v1.0.puml`
- `Report_ЛР1_Команда1_v1.0.pdf`

## Работа с ветками
- `main` - стабильная версия (только проверенный код)
- `develop` - основная ветка разработки
- `feature/название-функции` - для новых функций
- `bugfix/название-бага` - для исправлений

## Процесс работы
1. Создать ветку от `develop`: `git checkout -b feature/название`
2. Внести изменения
3. Закоммитить: `git commit -m "Краткое описание"`
4. Запушить: `git push origin feature/название`
5. Создать Pull Request (PR) в `develop`
6. Получить ревью от другого участника
7. Влить изменения
